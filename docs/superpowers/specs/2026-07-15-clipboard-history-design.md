# ClipBar — Menu Bar Clipboard History (Design)

Date: 2026-07-15
Status: Approved (brainstorming)

> `ClipBar` is a placeholder name; trivially changeable later.

## Purpose

A tiny native macOS menu bar app that keeps a short, in-memory history of
recent clipboard copies so a new copy never silently destroys the previous one.
Built from scratch (no third-party clipboard manager) for security: nothing is
ever written to disk, and the third-party code surface is zero.

## Goals / Non-goals

**Goals**
- Never lose a recent copy to a subsequent copy.
- Restore any recent item back onto the system clipboard with one click.
- Keep the security surface minimal: memory-only, no dependencies.

**Non-goals (YAGNI — deliberately excluded)**
- Disk persistence, encryption, sync.
- Search, pinning, favorites, categories.
- Preferences/settings window.
- Capture of file paths or arbitrary pasteboard types (only text + images).
- Built-in login-item management (offered as an optional script instead).

## Behavior

- **Captures:** text (plain/rich, stored as string) and images.
- **Retention:** keep at most **10 entries** AND drop anything older than
  **60 minutes** — whichever limit is reached first. Newest first.
- **Dedup:** copying content already present moves that entry to the top
  (with a refreshed timestamp) instead of adding a duplicate.
- **Secrets:** pasteboard content tagged by password managers as
  `org.nspasteboard.ConcealedType` **or** `org.nspasteboard.TransientType`
  (and `AutoGeneratedType`) is still captured and fully restorable, but is
  displayed **masked** in the menu (`🔒 ••••••••`) — the plaintext is never
  shown in the UI. (Decision: transient is treated the same as concealed,
  i.e. capture + mask, per "capture everything but mask".)
- **Restore:** clicking an entry writes its real payload back to
  `NSPasteboard.general` and closes the menu.
- **Menu also contains:** a separator, `Clear history`, and `Quit`.
- **Unsupported content** (files, other pasteboard types, empty/unreadable
  pasteboard): ignored, not captured.

## Architecture

macOS provides no "clipboard changed" notification, so change detection is by
polling `changeCount`.

### Components

1. **ClipboardMonitor** (executable target, thin glue)
   - A repeating `Timer` (~0.5s) reads `NSPasteboard.general.changeCount`.
   - Reads and classifies the pasteboard **only** when the count changes.
   - Classification order: concealed/transient markers → image → text →
     otherwise ignore.
   - Hands a new `Entry` to the `HistoryStore`.
   - Negligible CPU (an integer comparison per tick; full read only on change).

2. **HistoryStore** (core library, the only real logic — pure, testable)
   - In-memory, newest-first ordered list of `Entry`.
   - Enforces both caps: max 10 entries; prune entries older than 60 minutes.
   - Dedup: equal payload → move existing entry to top, refresh timestamp.
   - Expiry is applied on each insert and on menu open (no separate timer
     needed; the poll tick also triggers pruning).
   - No persistence; state lives only for the process lifetime.

3. **Entry** (core library, value type)
   - `id`, `timestamp`, `kind` (`.text` / `.image` / `.concealed`),
     the real payload for restore (String for text/concealed; image data for
     image), and a display preview:
     - text → single-line, whitespace-collapsed, truncated (~50 chars)
     - image → small thumbnail (~16px tall) + a size label (e.g. `Image 320×240`)
     - concealed → fixed mask string, no plaintext

4. **MenuController** (executable target, thin glue)
   - Owns the `NSStatusItem` in the menu bar.
   - Rebuilds the `NSMenu` on open from the current store contents.
   - Wires each entry item's action to restore its payload.
   - Adds `Clear history` and `Quit` items.

5. **App packaging**
   - Minimal `.app` bundle with `Info.plist` `LSUIElement = true` (no dock
     icon, menu bar only), produced by `scripts/bundle.sh` from the compiled
     executable.
   - `scripts/install-login-item.sh` (optional) installs a
     `~/Library/LaunchAgents` plist to launch the app at login — chosen over
     the `SMAppService` login-item API because that API is unreliable for a
     locally-built, unsigned app.

## Data flow

```
copy happens → changeCount increments
  → ClipboardMonitor (next tick) reads pasteboard
    → classify (concealed? image? text? else ignore)
      → build Entry
        → HistoryStore.insert(entry)   # dedup + enforce caps + expiry
menu opened
  → HistoryStore.prune()  → MenuController rebuilds NSMenu
    → user clicks entry
      → NSPasteboard.general set to entry payload  (menu closes)
```

Note: restoring changes `changeCount`, so the monitor will observe it and
dedup it to the top — harmless and expected.

## Memory considerations

Bounded by the 10-entry cap. Images store their original data for
full-fidelity restore, plus a small thumbnail for display. Worst case (10 large
images) is tens of MB — acceptable and bounded.

## Project structure

```
clipboard-history/                 # SwiftPM package (git repo root)
  Package.swift
  Sources/
    ClipHistoryCore/               # Entry, HistoryStore, classification, masking (pure logic)
    ClipBar/                       # AppDelegate, ClipboardMonitor, MenuController, main.swift (AppKit glue)
  Tests/
    ClipHistoryCoreTests/          # unit tests: caps, dedup-to-top, expiry, masking classification
  scripts/
    bundle.sh                      # wrap built binary into ClipBar.app (+ Info.plist, LSUIElement)
    install-login-item.sh          # OPTIONAL launch-at-login via LaunchAgent plist
  docs/superpowers/specs/          # this spec
```

Build/test from the command line (no full Xcode required):
`swift build`, `swift test`, then `scripts/bundle.sh` to produce `ClipBar.app`.

## Testing strategy

Test-driven on the core library, where all logic lives:
- `HistoryStore`: 10-entry cap; 60-minute expiry (using an injectable clock so
  time is controllable in tests); dedup moves an existing entry to top with a
  refreshed timestamp; ordering is newest-first.
- Classification/masking: concealed/transient markers → `.concealed` with a
  masked preview and preserved real payload; images → thumbnail + size label;
  text → truncated single-line preview.

The AppKit glue (`ClipboardMonitor`, `MenuController`) is kept deliberately thin
and delegates all decisions to the tested core, so it needs little or no direct
testing.

## Decisions locked during brainstorming

- Persistence: **memory only** (nothing on disk).
- Content: **text + images** (with thumbnails).
- Secrets: **capture + mask** (concealed and transient both masked, restorable).
- Retention: **10 entries AND 60 minutes**, whichever first.
- Stack: **native Swift, zero third-party dependencies** (AppKit `NSStatusItem`).
- Launch-at-login: **optional install script**, not a built-in toggle.
